# Interactive setup.sh + update.sh for VulnBrief

## Overview
Two self-contained, interactive bash scripts at the repo root, Docker-only (per your choice), plus a small backward-compatible change to the compose files so **port** and **Mongo URI** become configurable via `.env` (defaults identical to today — existing deployments unaffected).

## Committed config changes (enables port choice without editing tracked files on each machine)
- `docker-compose.yml` and `docker-compose.example.yml` (kept identical, as today):
  - `ports: - "${WEB_PORT:-9100}:9100"` (compose v2 interpolates from `.env` automatically)
  - `environment: LOCAL_MONGO_URI: ${LOCAL_MONGO_URI_DOCKER:-mongodb://host.docker.internal:27017/}`
- `.env.example`: document the two new optional vars (`WEB_PORT`, `LOCAL_MONGO_URI_DOCKER`) with comments.
- `README.md`: add a short "Interactive setup" note under Quick start (`./setup.sh`, later `./update.sh`).

## setup.sh (new, executable)
Interactive wizard, `cd` to repo root, colored output:
1. **Preflight**: `docker` installed + daemon running; `docker compose` (v2) with `docker-compose` fallback; abort with clear messages otherwise.
2. **Existing `.env` handling**: if `.env` exists, ask — keep it and just (re)build/start, or re-run the wizard (backing up to `.env.bak.<timestamp>` first). Never clobber silently.
3. **Web port prompt** (default 9100): validate numeric, check nothing is listening (bash `/dev/tcp` probe), write `WEB_PORT` to `.env`.
4. **MongoDB menu**:
   - *On this host (default)* → probe TCP 27017; if unreachable, offer to start the standalone container from docs/LOCAL_DEPLOY.md (`mongo:7`, named volume `webserver-local-mongo-data`, port 27017, container name `webserver-local-mongo`, handling a stopped existing container). `.env` gets `LOCAL_MONGO_URI=mongodb://localhost:27017/` and compose's `host.docker.internal` default works.
   - *Custom/remote URI* → prompt full URI (supports `mongodb://user:pass@host:port/`), probe host:port, write both `LOCAL_MONGO_URI` and `LOCAL_MONGO_URI_DOCKER` to `.env`.
5. **`FLASK_SECRET_KEY`**: auto-generate via `openssl rand -hex 32` (fallback: `/dev/urandom`) unless the user opts to supply one; never echoed to the screen.
6. **Initial admin account** (bootstrap user): defaults `admin`/`changeme`; offer to customize (writes `WEB_AUTH_BOOTSTRAP_USERNAME`/`WEB_AUTH_BOOTSTRAP_PASSWORD`), with a warning to avoid defaults.
7. **Optional integrations**: Tavily API key (Enter to skip); SMTP opt-in (`y/N`) → host/port/username/password/from/TLS prompts, skipped values stay empty as in `.env.example`.
8. Write `.env` from the `.env.example` template, `chmod 600`.
9. `docker compose up -d --build`, then a wait loop (~90s): container running + any HTTP response on `http://localhost:$WEB_PORT/` (the app's `/` 302-redirect counts as healthy; the API health endpoint requires login so it can't be used anonymously). On timeout, print `docker compose logs --tail=50 web` and exit 1.
10. **Summary**: app URL, bootstrap-login reminder, where settings live (`.env`, `config/config.json`), how to change the port later (`WEB_PORT` in `.env` + `docker compose up -d`), stop command.

## update.sh (new, executable)
1. Flags: `-y/--yes` (skip confirmations), `-h/--help`.
2. Preflight: inside a git repo, `.env` exists (else "run ./setup.sh first"), docker + compose available; `compose()` wrapper handles `docker compose` vs `docker-compose`.
3. Warn if `git status --porcelain` shows local modifications → confirm before continuing (untracked `newsletters/` HTML, `.env`, certs are safe and untouched).
4. `git fetch origin` → show pending commits (`git log --oneline HEAD..origin/main`); if already up to date, say so and offer rebuild/restart anyway or exit.
5. Confirm → `git pull --ff-only` (on failure, show a short fix hint and exit).
6. `docker compose up -d --build` (rebuild is mandatory — the image is built from source, never pulled).
7. Same health wait loop as setup (port read from `WEB_PORT` in `.env`, default 9100); on failure dump logs.
8. **Summary**: new HEAD short hash, container status, and the fact that no manual migrations are needed (Mongo indexes are ensured at startup; Mongo data, `newsletters/`, and `.env` are untouched by the update).

Both scripts share a few small duplicated helpers (colors, `die`, `confirm`, port probe, compose wrapper) so each remains standalone.

## Verification
- `bash -n` both scripts; run `./setup.sh` preflight paths where safe (no docker daemon changes without your say-so) and `./update.sh --help`, plus a dry check of the compose interpolation with `docker compose config` to confirm the defaults render identically to today's file.
